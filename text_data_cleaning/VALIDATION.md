# 텍스트 데이터 정제 개선·검증 기록

## 승인 범위와 업무 근거

2026-11-18 사용자가 현황 분석·개선 계획을 확인하고 실행 통합, 설정·프롬프트·입출력 분리, 결과 검증, 저장·재개 보호, 문서·테스트 작성 및 대체 Python 2개 정리를 승인했다. 구현 완료 후 폴더명 변경도 별도로 승인받아 `text_data_cleaning`으로 변경했다.

작업은 `master / 343547d`에서 시작했다. 이전 설문 응답 분류 작업의 통합·이름 변경과 `handoff.md` 변경이 이미 남아 있었고 이를 보존했다. 6번 폴더는 Python 2개만 있었으며 원본 CSV·Excel, 의존성 목록, README와 테스트는 없었다. 실제 업무 데이터는 이번 검증에 사용하지 않았다.

업무 설명은 [공유데이터 기록](../reference/records/gonggam-data/work/shared-data.md)의 기존 사용자 확인 내용에 근거한다. 기관 DB에서 확보한 공유데이터의 컬럼·내용을 검토하고, 장문 본문에 Python·LangChain을 활용해 HTML·개인정보 포함 문구 정제를 보조한 범위다. 후보 선정·기관 협의·컬럼 삭제·TEST 데이터 처리·등록 업무 전체가 이 코드에 구현되었다고 쓰지 않았다. 기관의 등록·승인·평가 실적과 개인의 정제 코드 기여를 구분하며 정제 정확도·처리시간·개인정보 삭제 완전성 성과를 추가하지 않았다.

## 변경 내용과 영향

| 항목 | 구현과 보존한 동작 |
| --- | --- |
| 실행 | `clean.py html / privacy`로 통합. 두 작업은 독립 실행하며 완료된 HTML 결과를 개인정보 정제에 연결 가능 |
| 설정 | 대상 컬럼·CSV 인코딩·Excel 시트·모델·timeout·프롬프트 경로를 설정. 기본 컬럼 `내용`, 인코딩 `cp949`, 첫 시트 유지 |
| 프롬프트 | 기존 두 지시문을 `prompts/html.md`, `prompts/privacy.md`로 분리. HTML 양식 제거와 개인정보가 포함된 문구 전체 삭제의 차이 유지 |
| 메시지 역할 | 작업 지시는 system, 입력 본문은 별도 user 메시지. 본문을 system 지시와 합치지 않으며 중괄호도 원문 그대로 전달 |
| 출력 구조 | HTML의 `content`, 개인정보의 `Preprocess_Content` 필드명 유지. 필수 엄격 문자열과 추가 필드 금지 적용. 누락·null·숫자·다른 필드명으로 본문이 사라지던 경로 차단 |
| 빈 결과 | 빈 문자열·공백만 반환되면 `review_required`와 `EMPTY_RESULT`. 정상적인 전체 문구 제거 가능성을 오류와 구분하며 자동 재호출하지 않음 |
| 잘못된 결과 | 형식·길이·저장 불가능 문자 오류는 `INVALID_RESULT`. API 실패는 `API_ERROR`. 해당 행의 data에는 원문을 유지하고 오류 상태 저장 |
| 입력 값 | CSV 자동 타입 추론 제거. 문자열 ID 앞자리 0·NA·쉼표·따옴표·줄바꿈 보존. Excel은 선택한 시트의 셀 값 유지. 빈 본문은 행을 삭제하지 않고 `skipped` |
| 입력 검증 | 없는 컬럼·비문자열 본문·중복 또는 빈 헤더·CSV 열 수 오류·수식·Excel 저장 한도 초과는 요청 전 거부. 긴 원문을 자동 절단하거나 무조건 문자열로 바꾸지 않음 |
| 파일 구조 | `data`는 원본 컬럼과 행 순서 유지, `processing`은 원본 행 번호·상태·결과·오류 코드, `run`은 실행 식별정보. 상태 컬럼을 원본 데이터 컬럼 사이에 끼워 넣지 않음 |
| 저장 | 요청 전 초기 체크포인트와 매 행 처리 결과 저장. 같은 파일에 세 시트를 함께 확정. 원본 파일은 변경하지 않음. 일반 오류 시 임시 파일·잠금 정리 |
| 재개 | 같은 입력 파일 해시·설정 및 프롬프트 해시·원본 행·상태·데이터 대응일 때만 `pending`·`error` 행 처리. 완료·검토 대상 행은 건너뜀. 첫 정제 오류에서 중단 |
| 결과 보호 | 기존 경로 자동 덮어쓰기 금지. 신규 파일은 하드 링크로 완성 파일만 확정, 명시적 재개는 원자적 파일 교체. 같은 출력 잠금 및 저장 전 외부 변경 해시 검사 |
| 다음 단계 | 미완료 또는 검토 대상이 있는 이 도구의 결과 파일은 직접 연결 거부. 사람이 확정한 별도 data 값 파일은 일반 입력으로 사용 가능 |
| 모델·키 | JSON model → 환경 변수 → 명시한 환경 파일 → 기존 기본값 `gpt-5.6-luna`. 키는 환경 변수 우선. 자동 env 탐색·환경 변경 없음. 실제 호출이 없는 빈 입력·완료 작업 재개는 키 불필요 |
| 요청 정책 | 체인은 작업당 한 번 생성. timeout 기본 60초, 자동 재시도 0. 구조화 출력의 `function_calling` 방식을 명시 |
| 로그·추적 | 코드가 원문·식별자·키·원격 오류 본문을 출력하지 않고 진행 건수·상태만 출력. 모델 호출 구간의 LangSmith 추적 비활성화 |
| 종료 코드 | `0`은 처리 완료, `1`은 오류·미처리·검토 대상이 남음, `2`는 실행 실패. 자동 처리 완료를 사람의 품질 검토 완료로 표시하지 않음 |

기존 두 파일에서 AST로 추출한 지시문을 구분선·본문 자리표시자 앞까지 비교해 **지시문 텍스트가 두 모드 모두 그대로 보존됨**을 확인했다. 메시지 역할 분리는 승인된 변경이며 실제 모델의 응답 품질이 전후 동일하다고 검증한 것은 아니다.

## 정리와 보존

- 새 실행은 `clean.py`, 설정은 `config.py`, 모델은 `model.py`, 입력·저장은 `storage.py`, 처리·재개는 `workflow.py`에 분리했다. Python 함수·메서드·클래스의 한국어 설명을 확인했다.
- 통합 검증 후 대체된 `llm_html.py`, `llm.py`를 삭제했다. 호환용 실행 파일은 남기지 않았다.
- CSV는 표준 라이브러리, Excel은 openpyxl을 사용한다. pandas와 중복 import는 제거했다. 실제로 사용한 의존성을 `requirements.txt`에 고정했다.
- 로컬 입력·출력·개인 실행 설정·환경 파일·Python 캐시만 대상 폴더의 `.gitignore`에서 제외한다. 루트 ignore와 이미 추적된 파일은 임의로 변경하지 않았다.
- **완료된 다섯 폴더와 `reference/`의 223개 파일 해시가 작업 전후 동일**하며 해당 영역에 추가된 파일도 없다. 기존 HWPX·Markdown·PDF와 설문 응답 분류 폴더의 로컬 가상 시각 점검 PNG도 포함한다. 해당 폴더의 테스트는 재실행하지 않았다.
- `reference/`의 역사 기록·공개 코드 링크는 수정하지 않았다. 실제 원본 데이터·개인정보·내부 산출물·비밀값을 예제와 문서에 옮기지 않았다.
- 사용자 승인에 따라 폴더명을 `text_data_cleaning`으로 변경하고 현재 인계 문서의 링크를 갱신했다. 이동 직후 **16개 파일의 해시가 변경 전과 모두 같음**을 확인했고, 그 뒤 검증 기록·인계 문서의 완료 상태만 갱신했다. 다른 다섯 폴더와 `reference/`의 223개 파일도 보존됨을 다시 확인했다. 커밋·푸시는 하지 않았다.

## 검증 환경과 조건

- Windows, Python 3.13.2.
- 전용 임시 환경: `%TEMP%\etc-text-cleaning-runtime\Scripts\python.exe`.
- 의존성: openpyxl 3.1.5, Pydantic 2.14.3, langchain-core 1.8.2, langchain-openai 1.8.1, OpenAI SDK 3.54.0, langsmith 0.15.0, python-dotenv 1.2.4, HTTPX 0.28.1.
- `uv pip check`: 설치된 41개 패키지의 호환성 확인. 기존 다섯 폴더의 가상 환경은 변경하지 않았다.

검증 전 파일 쓰기와 외부 API 호출 경로를 확인했다. 입력은 임시 폴더에서 만든 가상 CP949·UTF-8 CSV와 Excel이다. 실제 기관 파일·키는 사용하지 않았다. 소켓 연결과 HTTPX 실제 전송을 막고 `MockTransport` 또는 대체 정제 함수를 사용했다. 새 프로세스에서도 실제 OpenAI·LangChain·LangSmith 환경 설정을 제거하고 소켓 연결을 차단했다. 네트워크 응답을 모의한 시험이며 실제 API 성공 또는 개인정보 삭제 품질의 검증이 아니다.

## 미검증 범위와 한계

- 실제 API 인증·과금·모델 접근 가능성·응답 품질·개인정보 누락·과잉 삭제·HTML 내용 보존·처리시간 절감. 기본 모델명은 현재 원본 코드의 값을 보존한 것이며 과거 업무 사용 모델이나 현재 계정의 사용 가능성을 확인한 값이 아니다.
- 실제 기관 CSV·Excel·원천 DB 처리, 모든 컬럼의 개인정보 검토, CSS·TEST 데이터·불필요 컬럼 정제 전체. 이 도구는 설정한 본문 컬럼만 처리한다.
- Excel은 셀 값 중심이며 원본 서식·병합·도형·다른 시트를 복제하지 않는다. 수식과 저장 한도를 넘는 값은 거부한다. 긴 텍스트 자동 분할·재조합은 구현하지 않았다.
- 대용량·장시간 처리 성능과 매 행 전체 Excel 저장 비용, 다른 운영체제·네트워크 드라이브·하드 링크를 지원하지 않는 파일시스템은 미검증이다.
- 원격 응답 수신 직후 저장 전에 프로세스가 강제 종료되면 해당 행이 재호출될 수 있다. 원격 요청의 정확히 한 번 실행을 보장하지 않는다.
- 강제 종료·전원 차단 시 남은 잠금·임시 파일은 실행 중인 작업이 없는지 확인한 뒤 운영자가 정리한다. 정상 예외·사용자 중단의 정리는 검증했다.
- 외부 프로그램과의 동시 편집은 지원하지 않는다. 해시 검사는 확인 시점의 변경을 감지하며 비협조적인 모든 외부 쓰기와의 경쟁을 완전히 잠그는 기능은 아니다.
- 체크포인트의 data에 실패·대기 행의 원문이 남을 수 있다. 결과와 상태를 검토한 뒤 사용하며 자동 완료 상태를 배포 적합성이나 개인정보 삭제 완전성으로 간주하지 않는다.
- 승인된 폴더명 변경과 새 경로의 검증을 완료했다. 앞서 완료된 다섯 폴더의 테스트는 이번에 재실행하지 않았다.
