# 프로젝트: 제주도 관광지 추천 웹서비스 개발

상태: 작성 완료 (사용자 확인, 2026.11.02). 친구가 만든 기초 프런트엔드에 본인이 배포한 백엔드를 연결해 외부에서 사용할 수 있는 웹 MVP를 완성했다. 본인의 데이터·추천 모델·API·Docker·AWS 배포 및 연동, 후속 모바일 앱·경로 최적화 개발 중단과 공개 범위를 반영했다. 성능 수치는 자료 간 평가 절차 차이가 있어 검증 전 참고값으로 유지한다.

## 기본 정보

- 프로젝트명: 제주도 관광지 추천 웹서비스 개발
- 공개용 프로젝트명: 제주도 관광지 추천 웹서비스 개발 (사용자 공개 확인, 2026.11.02)
- 수행 기간: 2023.09 ~ 2023.11 (과거 이력서·포트폴리오 기준). 정확한 착수일·중단일은 확인되지 않았다.
- 소속 회사 또는 기관: 개인 협업 프로젝트. 코리아리서치인터내셔널 퇴사 후 친구와 앱 출시를 목표로 시작했다.
- 고객사 또는 적용 업무 분야: 여행자의 특성과 취향에 맞는 관광지 추천 및 여행 계획 지원. 첫 대상 지역은 제주도였다.
- 팀 규모 및 구성: 본인과 친구 1명, 총 2명 (사용자 설명). 본인은 데이터·추천 모델·백엔드 개발과 배포·연동을 맡았다. 친구는 기초 프런트엔드를 구현했고 후속 모바일 앱도 맡기로 했으나 취업 후 후속 개발이 중단되었다. 친구의 이름은 기록하지 않는다.
- 본인의 역할: AI-Hub 데이터 수집·정제, 데이터 분석·특성 탐색, 머신러닝 추천 시스템 개발, FastAPI 학습·API 구현, Dockerfile 작성·AWS Lambda 배포, 기초 프런트엔드와 배포한 백엔드 연동
- 관련 회사 경력 또는 학력 기록: [코리아리서치인터내셔널 경력](employment-korea-research-international.md) 이후의 개인 개발 경험으로 연결한다.

## 문제와 목표

- 프로젝트가 시작된 배경과 문제: 퇴사 후 친구와 앱을 출시하기로 뜻을 모았고, AI-Hub의 관광·여행 로그 데이터를 발견해 제주도부터 개발을 시작했다 (사용자 설명). 여행자가 방문할 지역에서 자신의 특성과 취향에 맞는 관광지를 고르고 여행 계획을 세울 수 있는 서비스가 목표였다.
- 달성하려는 목표 및 성공 기준: 여행자 특성을 입력하면 적합한 관광지를 추천하고, 이후 여행 일정에 맞춰 경로를 제시하는 앱으로 확장한다. 데이터·모델·API 개발과 배포 후 친구가 만든 기초 프런트엔드를 연결해 외부 접속으로 추천을 사용해볼 수 있는 웹 MVP를 완성했다 (사용자 확인). 모바일 앱과 일정 기반 최적 경로 기능은 후속 개발 계획으로 남았다.
- 주요 제약 조건: 불완전한 여행 로그·관광지 정보의 정리, 방문 이력이 없는 신규 사용자에게 적용할 추천 방법 필요, FastAPI·백엔드 개발과 다양한 AWS 서비스의 선택·학습, 초기 배포의 구동 실패, 공동 개발자의 일정 변화에 따른 후속 개발 지속의 어려움

## 본인의 책임과 주도 경험

- 직접 책임진 범위: 데이터 수집·정제와 머신러닝 추천 시스템을 맡았고, FastAPI를 학습해 백엔드 개발, Dockerfile 작성과 AWS Lambda 배포, 친구가 만든 프런트엔드와의 연동까지 수행했다 (사용자 확인). 구체적인 알고리즘은 사용자가 기억하지 못했으나, 과거 포트폴리오와 공개 코드에서 CatBoost 기반 추천 구현을 확인했다.
- 직접 수행한 작업:
  - AI-Hub 국내 여행로그 데이터 확보 및 MySQL 기반 데이터 구성·관리
  - 여행·여행자 정보 결합, 다중 선택 항목의 분해·인코딩, 관광지·평점 데이터 구성
  - 카카오 지도 검색으로 관광지 식별 정보를 보완하고 검색되지 않거나 제주도가 아닌 방문지 정리 (과거 자료·코드)
  - 주요 변수 탐색 및 여행자·관광지 군집 분석 실험
  - CatBoost·LightFM·DeepFM 관련 추천 모델 실험과 최종 CatBoost 모델 구성
  - 신규 사용자 특성과 관광지 정보를 결합해 카테고리별 상위 5곳을 반환하는 FastAPI 구현
  - Docker·Mangum 기반 AWS Lambda 실행 구성 및 AWS 백엔드 배포
  - 친구가 구현한 기초 프런트엔드에 배포한 백엔드를 연결해 외부에서 사용 가능한 웹 MVP 구성
- 핵심 의사결정과 그 이유:
  - **첫 지역을 제주도로 제한**: 공동 개발의 첫 대상 지역을 제주도로 정해 여행 로그 기반 추천을 구현했다 (사용자 설명).
  - **신규 사용자 특성에 기반한 추천**: 포트폴리오는 당시 실험에서 과거 만족도 정보가 없는 여행자의 추천을 고려해 CatBoost를 선택했다고 설명한다. 실제 API도 성별·연령대·동반 유형·여행 스타일·동기 등 입력 특성을 사용한다. 이를 LightFM·DeepFM 일반의 한계로 확대하지 않는다.
  - **모형을 API로 연결**: 추천 모델을 앱에서 사용할 수 있도록 FastAPI를 익혀 입력·응답 스키마, 관광지 조회, 예측·상위 결과 반환을 구현하고 AWS에 배포했다.
  - **Docker 기반 배포로 전환**: 처음 AWS에 배포했을 때 구동되지 않는 문제를 겪었다. Docker를 학습해 Dockerfile로 실행 구성을 작성하고 AWS Lambda에 배포해 동작을 확인했다 (사용자 추가 설명). 초기 실패의 구체적인 오류·원인은 현재 자료로 확정하지 않는다.
- 팀 또는 고객과 조율한 내용: 친구와 앱 출시 목표를 공유하고 역할을 나누었다. 친구가 만든 기초 프런트엔드에 본인이 배포한 백엔드를 연결해 웹 MVP를 외부에서 사용할 수 있게 했다. 이후 친구가 취업하면서 후속 모바일 앱·일정 기반 경로 기능의 개발을 이어가기 어려워졌다 (사용자 설명).
- 어려움과 이를 해결하기 위해 취한 행동: 데이터 정제 과정에서 불완전한 여행 기록과 검색되지 않는 관광지 정보를 수정·제외했다 (과거 자료·코드). FastAPI를 배우며 DB 연동과 백엔드 개념을 익히는 데 흥미를 느꼈고, 가장 큰 어려움은 다양한 AWS 서비스 중 필요한 것을 선택해 학습하고 배포하는 과정이었다. 초기 배포에서 구동되지 않은 뒤 Docker를 익혀 Dockerfile을 작성하고 Lambda 배포에 성공했다. 사용자는 이 과정이 매우 어려웠지만 성공했을 때 큰 성취감을 느꼈다고 설명했다 (2026.11.02).

## 수행 방법

- 사용한 데이터의 종류 및 규모: AI-Hub의 국내 여행로그 데이터 중 제주도·도서지역 관련 자료. 여행·여행자 특성, 방문지 정보, 만족도·재방문 및 추천 의향 등이 포함된다. 포트폴리오 7쪽의 정제 완료 표에는 여행지 1,318곳·여행객 2,457명·평점 12,587건이 기재되어 있다. 코드에서는 TRAVEL_ID를 사용자 특성·평점 결합 키로 사용하므로 집계 단위는 해당 자료·구현 기준으로 설명한다. 당시 내려받은 데이터의 정확한 버전은 확인되지 않았다.
- 분석 방법 또는 AI 접근 방법: 여행자·관광지 특성으로 방문 만족도를 예측하고 점수가 높은 관광지를 추천하는 접근. CatBoost 회귀 모형, 변수 중요도 탐색, K-Modes·K-Prototypes 군집 분석 실험, LightFM·DeepFM 추천 실험 코드가 있다. 포트폴리오는 군집 번호의 파생변수 활용도 설명하지만, 최종 학습 파일·배포 입력에 반영된 버전의 일치 여부는 확인되지 않았다.
- 사용한 기술 및 도구: Python·pandas, MySQL, CatBoost, Hyperopt, kmodes, LightFM, TensorFlow·LibRecommender, FastAPI, Pydantic, SQLAlchemy, Docker, Mangum, AWS Lambda. 알고리즘 실험과 배포에 사용한 도구를 구분해 설명한다.
- 방법을 선택한 이유: 방문 이력이 없는 사용자도 자신의 특성을 입력해 추천을 받을 수 있도록 만족도 예측 기반 방법을 사용했다는 설명이 과거 포트폴리오에 있다. CatBoost 모델 파일을 API에 연결해 관광지 특성과 사용자 입력을 결합한 예측을 제공한다.
- 결과를 검증한 방식 및 비교 기준: 과거 포트폴리오는 모형별 R²·RMSE 비교와 최종 CatBoost의 10-fold 교차검증 추정치를 제시한다. 공개 코드에는 모형마다 서로 다른 분할·목표변수·지표가 있어 아래와 같이 구분한다. 이번 작업에서 모델 재학습·정제 파일 집계·배포 API 호출을 통한 재현은 수행하지 않았다.

### 평가 자료의 차이와 성능 표기

| 자료 | 확인되는 평가 구성 | 해석 범위 |
| --- | --- | --- |
| 포트폴리오 9~10쪽 | 비교 설계에 Train : Validation : Test = 70 : 15 : 15, R²·RMSE 기재. 최종 CatBoost 성능은 10-fold CV 추정 R² 0.81·RMSE 1.02로 표기 | 당시 문서의 기재값으로 보존. 현재 재현·검증한 확정 성능으로 제시하지 않음 |
| [Catboost.py][model-code] | 80:20 학습·검증 분리, 검증 RMSE로 Hyperopt 탐색, 전체 데이터의 10-fold CV, 전체 데이터로 최종 모형 학습·저장 | 포트폴리오의 70:15:15 설계와 동일한 절차라고 확정할 수 없음 |
| [Light_FM.py][lightfm-code] | 상호작용 자료 80:20 분리. AUC·precision@10·recall@10 계산 | 공개 코드만으로 포트폴리오의 공통 R²·RMSE 비교를 재현한 자료가 아님 |
| [Deep_FM.py][deepfm-code] | 최고 평점인 5를 1, 나머지를 0으로 변환한 ranking 설정. 90:10 분리와 balanced accuracy·ROC-AUC·PR-AUC 등 계산 | CatBoost의 원래 평점 회귀와 목표변수·평가 구성이 다름 |

평가 데이터의 사용자·관광지 독립성, 파생변수 생성과 분할의 순서, 배포 입력과 학습 특성의 최종 버전 일치 여부는 확인되지 않았다. 문서의 비교 그림과 공개 실험 스크립트가 동일한 평가 실행을 가리킨다는 근거가 확보되기 전에는 ‘다른 모형보다 검증된 우위’나 ‘신규 사용자 성능 R² 0.81’로 확대하지 않는다. 사용자는 당시 성능이 나쁘지 않았던 것으로 기억한다고 설명했다.

확인 기준은 저장소 커밋 `82a75ed23ac66b99c879ec7e7266fb2ca481903c`이다.

| 구성 | 코드에서 확인되는 내용 | 근거 |

| 후보 데이터 구성 | 선택한 카테고리의 관광지 정보를 DB에서 조회하고 사용자 입력과 결합 | [recommend_crud.py][api-code] 15~33행 |

| 결과 구성 | 관광지 정보와 추천 점수를 결합해 반환. 1~5 점수는 0~100으로 선형 환산 | 같은 파일 57~78행. 환산 점수는 확률이나 모델 정확도가 아님 |
| Lambda 실행 구성 | FastAPI 앱을 Mangum으로 연결하고 Lambda Python 기반 Docker 이미지에 코드·모델을 포함 | [main.py][app-code] 1~27행, [Dockerfile][dockerfile] 1~15행 |

실제 배포와 웹 연동 완료는 사용자 추가 설명과 과거 포트폴리오에 근거한다. 초기 배포 실패 후 Docker를 익혀 Dockerfile을 작성하고 Lambda에서 구동했으며, 친구의 기초 프런트엔드와 연결해 외부에서 사용할 수 있었다 (사용자 확인, 2026.11.02). 공개 코드는 해당 구성을 뒷받침하며, 현재 AWS 자원의 운영 상태·배포 설정·응답 지연·사용자 수까지 확인한 자료는 아니다.

- 위 결과 중 본인의 기여로 설명할 수 있는 부분: 데이터 준비·분석·추천 모델 개발, API 구현·배포와 프런트엔드 연동. 친구가 만든 기초 프런트엔드와 본인이 만든 백엔드가 결합해 웹 MVP로 동작했다. 기존 포트폴리오의 기여도 백분율 대신 구체적인 담당 업무로 설명한다.
- 수치 외에 확인 가능한 업무 또는 조직의 변화: 데이터 분석·모델 개발에서 백엔드·컨테이너·클라우드 배포와 화면 연동까지 수행 범위를 넓혀 외부에서 사용할 수 있는 추천 서비스를 구현했다.
- 한계 및 개선할 점: 후속 모바일 앱과 일정 기반 경로 기능이 완성되지 않았다. 웹 MVP는 당시 외부 사용이 가능했으나 현재 운영 상태와 사용자 규모·반응은 확인되지 않았다. 성능 수치는 문서와 코드 사이 평가 절차 차이가 있어 재검증이 필요하다.

## 채용 담당자용 요약

- 한 문장 요약: 제주도 개인화 추천 모델과 FastAPI 백엔드를 개발하고 Docker·AWS Lambda 배포 및 프런트엔드 연동을 수행해 외부에서 사용할 수 있는 웹 MVP를 완성했다.
- 문제, 본인의 역할, 결과를 연결한 짧은 설명: 친구와 여행 앱 출시를 준비하며 제주도부터 개인 취향에 맞는 관광지 추천을 구현했다. 본인은 여행 데이터를 정제하고 CatBoost 모델·FastAPI 백엔드를 개발했다. 초기 배포 실패 후 Docker를 학습해 Lambda에서 구동하고 친구가 만든 기초 프런트엔드와 연결해 외부에서 사용할 수 있는 웹 MVP를 완성했다. 후속 모바일 앱·경로 기능은 공동 개발 일정 변화로 중단되었다.
- 이 경험에서 드러나는 역량: 추천 문제의 모델링, 데이터 정제·분석, 새로운 백엔드·컨테이너 기술 학습, 모델·DB·API·프런트엔드 연결, 클라우드 배포 문제 해결, 협업 역할 분담
