## 핵심 기여

- 직접 책임진 실무: 기관 DB 메타데이터의 테이블명·컬럼명에서 공유 후보를 찾고 민감성·데이터 규모·기존 외부 공개 여부를 검토했다. 확보한 데이터의 불필요·민감 컬럼, HTML·CSS, TEST 데이터, 정리되지 않은 값과 개인정보를 검토·처리한 뒤 공유시스템에 등록했다.
- 기관 실무자와의 소통·조율: 본인이 후보를 전달하면 기관 담당자가 보유 실무부서에 데이터를 요청했다. 제공이 거절되면 후보를 다시 선정·요청하고 목표 수를 확보할 때까지 반복했다. 필요하면 기관을 직접 방문해 업무의 필요성과 민감정보 제외·삭제 전처리 방안을 설명하며 협조를 구했다. 이는 공통 경험이며 특정 기관의 개별 사건으로 배정하지 않는다.
- 기술 기여: Python으로 데이터 정제·개인정보 포함 여부 검토 코드를 작성했고, 셀마다 긴 본문이 있는 컬럼은 LangChain을 활용해 HTML·CSS 정제와 개인정보 확인·삭제 작업을 보조했다. 공개 대표 코드는 HTML 제거와 개인정보 포함 문구 삭제를 요청하는 구조화 출력 구현으로 연결한다.
- 등록·승인까지의 과업 완수: 통상 5~8월에 후보 발굴·반복 요청·협의로 데이터를 확보하고, 확보 데이터의 정제를 마친 뒤 기관공유데이터관리시스템에 등록했다. 승인 후 국가공유데이터플랫폼에서 기관 간 검색·다운로드가 가능해지는 과정으로 연결했다. 기관별 등록·승인 완료와 지표 만점은 기존 Excel 기재값을 따른다.

## 문제와 반복 수행한 업무

### 기관의 요구와 해결할 문제

기관 정보시스템에서 관리하는 데이터를 다른 공공기관이 활용할 수 있는 공유데이터로 마련하고, 기관별 목표에 맞춰 공유시스템에 등록하는 업무다. 후보가 있어도 보유 실무부서에서 민감성 등의 사유로 제공을 거절하는 경우가 많았고, 확보한 DB 추출본도 바로 등록할 수 있는 상태가 아닌 경우가 있었다. 본인은 후보 재선정·기관 설명으로 데이터를 확보하고 가공·등록까지 이어갔다 (사용자 보완 답변, 2026.11.04).

2026년 편람은 기관이 현안 대응·정책 결정·행정업무 혁신 등에 활용할 필요가 있다고 판단해 생성·가공 후 공유한 데이터 건수를 평가한다. 등록 시 정보시스템명·DB명·테이블명·컬럼명 등의 메타데이터 입력이 필요하며, 기존 공동활용시스템 등록 데이터 및 같은 영역의 AI 친화적 행정문서 공유 실적과 중복할 수 없다고 설명한다. 이는 해당 연도 지표의 요구사항이며 개인이 수행한 세부 검토 절차를 직접 입증하는 자료는 아니다.

### 실제 담당 범위와 반복 수행 과정

1. **기관 DB 메타데이터에서 후보 테이블을 선정한다.** 기관이 운영하는 DB의 메타데이터를 받아 테이블명·컬럼명을 검토했다. 민감하지 않은지, 3열·50행 이상의 데이터 규모를 확보할 수 있는지, 홈페이지 등에 이미 공개된 내용인지 등을 고려했다. 외부 공개 여부는 보유 부서의 협조를 구할 때 활용한 판단 근거다.
2. **기관 담당자를 통해 보유 실무부서에 데이터를 요청한다.** 본인이 후보군을 전달하고 기관 담당자가 해당 실무부서에 요청했다. 공유 실적은 기관 정보시스템 DB에서 관리하는 테이블의 추출 데이터여야 한다는 조건을 기준으로 확보했다. 홈페이지 공개 여부를 확인한 것과 홈페이지 수집본을 공유 실적으로 제출한 것은 구분한다.
3. **거절 사유에 대응해 후보를 다시 선정·요청한다.** 민감한 데이터 등의 사유로 요청이 거절되는 경우가 많아 다른 후보를 찾아 요청하는 과정을 목표 수를 확보할 때까지 반복했다. 필요하면 직접 기관에 방문해 데이터 공유의 필요성과 민감정보를 제외·삭제하는 전처리 방안을 설명해 데이터 확보를 추진했다.
4. **확보 데이터의 컬럼·내용을 검토하고 정제한다.** 의미가 없거나 지나치게 민감한 컬럼은 삭제하고 남길 컬럼은 정제·개인정보 포함 여부를 확인했다. DB 추출본에 남아 있는 HTML·CSS, TEST 데이터, 정리되지 않은 값과 개인정보 등을 처리했다.
5. **장문 텍스트 정제에 Python·LangChain을 활용한다.** Python 코드를 작성해 데이터를 검토·정제했고 게시글 본문처럼 셀마다 텍스트가 긴 컬럼에는 LangChain을 활용했다. HTML·CSS 정제와 개인정보 확인에 사용했다는 실제 적용 설명과 아래 공개 대표 코드에서 확인한 구현을 구분한다.
6. **기관공유데이터관리시스템에 등록해 승인으로 연결한다.** 정제가 끝난 데이터를 정해진 양식으로 등록했다. 사용자 설명에 따르면 승인 후 국가공유데이터플랫폼으로 넘어가 공공기관이 다른 기관의 데이터를 검색·다운로드할 수 있다. 실제 타 기관 이용 실적은 별도로 확인하지 않았다.

3열·50행 이상은 사용자가 설명한 당시 실무 선정·확보 기준이다. 제공된 2026년 편람의 해당 절에서 직접 확인한 메타데이터·기한 등의 항목과 구분해 기록한다. 후보 단계의 민감성 판단과 확보 후 원데이터 검토·정제도 구분한다.

### Python·LangChain 대표 코드 확인

사용자가 SH에서 긴 텍스트를 정제할 때 사용한 업무 코드의 대표 사례로 [ETC의 Data_Cleaning_Langchain 폴더](https://github.com/wjdgks1999-cpu/ETC/tree/master/6.%20Data_Cleaning_Langchain)를 제공했다. 2026.11.04 현재 폴더의 두 파일을 읽고 커밋 `0f074315cb1175fba37c542d9e0e3bc9ce40108d`에서도 같은 내용을 확인했다.

## 기관 실무자와의 소통·설명·조율

- 직접 소통한 대상·분담: 본인은 공유 후보를 선정해 기관 담당자에게 전달했고, 기관 담당자가 데이터를 보유한 실무부서에 요청했다. 확보가 어려우면 본인이 기관에 방문해 필요성과 전처리 방안을 설명한 경험도 있다. 모든 보유 부서와 본인이 직접 연락했다고 일반화하지 않는다.
- 확인한 공통 책임: 2025년부터 대부분의 담당 지표에서 수행 방법·일정을 기관에 설명·설득하고 활동·산출물·기관 확인·제출까지 진행했다. 2026년에는 맡은 모든 지표를 독립적으로 수행했다.
- 확인한 제약: 민감성 등의 이유로 보유 부서의 제공 거절이 잦았고 기관별 목표 수의 데이터를 확보해야 했다. 확보 데이터에도 컬럼·본문 정제와 개인정보 확인이 필요했다.
- 본인이 설명·조율한 내용: 테이블·컬럼명에 근거한 후보군, 이미 외부에 공개된 내용인지 여부, 공유 업무의 필요성, 민감정보 제외·삭제 전처리 방안. 거절되면 대체 후보를 찾아 다시 요청하고 필요한 경우 방문 설명으로 협조를 구했다.
- 후속 조치: 확보한 데이터를 검토해 불필요·민감 컬럼을 삭제하고 내용·개인정보를 정제한 뒤 등록했다. 이는 사용자 설명의 공통 수행 과정이며 특정 기관의 거절 사유·방문·합의 내용을 새로 만들지 않는다.
- 확인된 결과: S6 각 행의 등록·승인 완료. 최종 승인을 본인이 승인 권한을 행사한 것으로 표현하지 않는다.

- 5~8월은 사용자가 설명한 후보 발굴·협의·확보의 통상 기간이다. 가공·등록·승인에 별도의 공통 월을 부여하거나 편람 기한을 개인의 실제 승인일로 대체하지 않는다.
- 목표 수를 확보할 때까지 후보 선정·요청을 반복하고, 확보가 어려운 경우 방문 설명을 통해 후속 조치를 이어간 경험으로 관리 행동을 설명한다. 실제 등록·승인 완료와 지표 결과는 Excel을 따른다.
- 등록 후 검토기관의 보완요청 사례는 별도로 제시되지 않아 구체적인 대응 일화는 생략한다. 이미 답변한 발굴·협의·가공 과정을 다시 인터뷰하거나 추가 완료율·시간 절감 수치를 만들지 않는다.

## 채용 담당자용 요약

- 한 문장: 기관 DB에서 공유 후보를 찾고 제공 거절에 재선정·반복 요청·방문 설명으로 대응했으며, 확보 데이터를 Python·LangChain으로 정제해 공유시스템 등록·승인까지 추진했다.
- 짧은 서술: DB 메타데이터의 테이블명·컬럼명을 바탕으로 민감성·규모·외부 공개 여부를 고려해 공유 후보를 선정했다. 기관 담당자를 통한 요청이 보유 부서에서 거절되면 후보를 다시 찾고 요청을 반복했으며, 필요하면 기관에 방문해 업무의 필요성과 민감정보 제외·삭제 방안을 설명했다. 통상 5~8월에 이러한 협의를 이어가며 목표 수의 데이터를 확보했다. DB 추출본의 불필요·민감 컬럼과 HTML·CSS·TEST 데이터·개인정보 등을 정제하고, 긴 본문에는 Python·LangChain을 활용했다. 정제한 데이터를 기관공유데이터관리시스템에 등록해 승인으로 연결했으며 기관별 목표·결과는 Excel의 등록·승인 실적으로 확인한다.
- 드러나는 역량: 메타데이터 기반 후보 발굴, 제공 제약에 대응하는 반복 협의·방문 설명, 데이터 확보와 후속 작업 추진, Python·LangChain 장문 정제, 공유시스템 등록·결과 관리.
