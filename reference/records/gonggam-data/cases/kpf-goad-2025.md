# 특이 사례: 한국언론진흥재단 GOAD 문의 직접 분석

[공감데이터 이력 안내](../README.md) · [상위 담당업무: AN](../work/analysis-policy-use.md) · [기관 이력표](../institutions-by-year.md)

사례 ID: `GG-2025-12-AN`. 2026.11.16 사용자의 요청으로 기존 AN 기록에서 상세를 분리했다. 수행 사실은 2026.11.04에 확인한 승인 기록을 이관했으며, 새로운 분석 실행이나 보고서 원문 재검증 결과가 아니다.

## 일반 업무와 다른 점

일반 AN 업무는 기관이 이미 수행한 분석과 실제 정책활용의 연결을 찾아 기관 확인·공식 문서화·등록·사후관리·평가 제출로 이어가는 컨설팅이다. 이 사례에서는 기관이 제공 가능한 데이터 후보를 전달한 뒤 본인이 분석 주제를 선정하고 데이터를 직접 분석했다.

| 구분 | 이 사례에서 확인된 내용 |
| --- | --- |
| 기관·연도 | 한국언론진흥재단, 2025년 |
| 업무 | 데이터 분석·정책활용 실적 및 성과(AN) |
| 분석 대상 | 정부광고통합지원시스템(GOAD)의 광고상담·기능 문의 |
| 실제 분석기간 | 결과보고서에 기재된 2025년 6~8월. 계획서의 예정 기간 7~8월과 구분 |
| 본인 기여 | 주제 선정, 데이터 분석, 결과 설명·개선안 전달, 기관 반영 결과의 보고서 작성·전달 |
| 기관 기여 | 분석 결과를 바탕으로 UI·UX 및 사용자 매뉴얼 개선 반영 |
| 구분할 성과 | 직접 분석 1건의 실적화·등록. 토픽 수, 지표 평가 결과, 기관 전체 등급을 구분 |

이 사례의 방법을 나머지 AN 기관에 적용했다고 일반화하지 않는다. 평가제도 배경은 [평가 개요](../evaluation/overview.md)를 읽되, 2026년 편람의 배점·인정기간을 이 2025년 수행에 소급하지 않는다.

## 상세 수행 기록

**문제와 담당 범위.** 한국언론진흥재단이 운영하는 정부광고통합지원시스템(GOAD)의 반복 문의에서 이용 불편과 개선 대상을 파악하는 과제다. 기관이 제공 가능한 데이터 후보군을 전달한 뒤 본인이 이 분석 주제를 선정하고, 기능 문의·광고 상담 및 문의 데이터를 직접 분석했다. 결과보고서의 분석기간은 2025년 6~8월이다.

**데이터와 분석.** 광고 상담·문의는 2019년 1월~2025년 6월, 기능 문의는 2019년 7월~2025년 6월 축적된 시스템 DB 자료다. 결과보고서에서 확인한 방법과 산출물은 다음과 같다.

| 단계 | 확인한 방법·산출물 | 근거 |
| --- | --- | --- |
| 전처리 | HTML 태그·특수문자·불필요한 공백 등 정제, Kiwi 형태소 분석·토큰화·정규화. 분석 프로세스 도식에는 중복 데이터 제거도 제시 | R2 2쪽 |
| 빈도·키워드 분석 | 연도·월별 문의 건수 추이, 키워드 출현 문서 빈도, TF-IDF 중요도와 연도별 순위 변화, 워드클라우드 등 시각화 | R2 2~6쪽 |
| 토픽모델링 | 사전학습 문장 임베딩, UMAP 차원 축소, HDBSCAN 군집화, 토픽 라벨·대표 문장 도출을 포함한 BERTopic 분석 | R2 2쪽·7~8쪽 |
| 결과 해석 | 광고상담 12개·기능 문의 13개 토픽을 정리하고 연도별 문의 빈도 변화를 분석. 기능 문의의 사용자·권한 관리와 계약·업무 관리 등 반복 주제 식별 | R2 7~10쪽 |
| 업무 활용 연결 | 분석 결과를 GOAD 고도화의 UI·UX 개선 요구사항과 사용자 매뉴얼 최신화에 반영한 내용을 정리 | R3 1쪽·4~6쪽 |

분석결과보고서에 기재된 Python·Kiwi·BERTopic을 수행 방법으로 사용한다. 계획서의 예시 모델명이나 최적화·평가 계획을 실제 사용 모델·검증 결과로 확정하지 않는다. 12개·13개는 보고서에서 확인한 토픽 수이며 새 분석으로 재현한 값이 아니다. 문의 원문·대표 문장·개별 이용자 정보는 이력에 옮기지 않는다.

**분석에서 활용으로 이어진 결과.** 광고상담과 기능 문의를 분리해 반복 수요를 구조화했다. 기능 문의에서는 사용자·권한 및 업무 이관 관련 문제가 주요 개선 근거로 이어졌으며, 정책활용결과보고서에는 업무이관 화면의 검색 조건·결과 항목 및 등록 UI 개선과 매뉴얼 개편이 제시되어 있다.

본인은 분석 결과를 기관에 설명하고 개선안을 전달했다. 이후 재단이 수행한 개선 반영 내용을 전달받아 보고서로 작성해 기관에 전달했다 (사용자 보완 답변, 2026.11.04). 주제 선정·직접 분석·결과 설명·개선안 전달·활용 결과 보고로 이어지는 본인의 기여와 실제 UI·매뉴얼 개선 반영을 수행한 기관의 역할을 구분한다. 주제 협의부터 활용 증빙·최종 제출까지 대부분을 맡았다는 사용자 설명과 S5의 실적화·등록·최종 자료 제출 기재를 함께 근거로 사용한다.

**완수·평가와 한계.** S5!H14에는 직접 분석 1건의 실적화·등록, 정량 만점 및 정성보고서·증빙 제출·정성 ‘우수’가 기재되어 있다. UI·UX 구현이나 매뉴얼 개편을 본인이 직접 개발한 것으로 표현하지 않는다. 문의 감소율·만족도·처리시간 개선과 같은 사후 효과, 특정 임베딩 모델·설정값, 현재 코드 실행 가능성은 확인하지 않았다.

## 소통·일정과 완수 근거

기관의 데이터 후보 제시 → 본인의 주제 선정·직접 분석 → 결과와 개선안 설명·전달 → 재단의 개선 반영 → 반영 결과를 받아 보고서 작성·전달로 연결했다. 주제 협의부터 활용 증빙·최종 제출까지 대부분을 맡았다는 사용자 설명을 위의 구체적인 본인 행동 및 Excel의 실적화·등록·최종 제출 기재와 함께 해석한다.

분석기간 2025년 6~8월을 전체 사업 참여기간이나 최종 제출일로 대체하지 않는다. 일반 AN의 통상 일정과 이 사례의 실제 날짜를 구분하며, 미확인 갈등·지연 대응·회의 일화는 추가하지 않는다.

## 공개 범위와 확인하지 않은 내용

- 회사·기관명과 허용된 방법·기여·결과의 취합·재서술은 기존 사용자 승인 범위를 따른다.
- 보고서 원문 파일·페이지 이미지·캡처·시스템 화면·다운로드 링크는 공개하지 않는다. 문의 원문·이용자 정보도 포함하지 않는다.
- 본인이 UI를 개발하거나 매뉴얼 개선을 직접 구현했다고 표현하지 않는다.
- 문의 감소율·만족도·처리시간 개선, 특정 임베딩 모델·설정, 현재 코드 실행 가능성과 성능은 미확인이다.
- 아래 자료 위치는 내부 근거 탐색용이다. 새 사례 파일을 공개 사이트나 챗봇 지식에 자동 추가하지 않았다.
