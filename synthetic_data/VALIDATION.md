# 구현·검증 기록

## 승인 범위와 변경 영향

사용자는 현황 분석 후 구조 개선과 다음 네 가지 계산 변경을 승인했다.

| 항목 | 적용 결과 | 영향 |
| --- | --- | --- |
| 위험도 보정 | 50:50 분할 임계값 산정에만 `1-(1-p)^2` 적용 | 전체 원본 대상 실제 평가값은 재보정하지 않음 |
| 혼합형 관계 | `sqrt(SSB/SST)`를 `SSB/SST`로 변경 | 혼합형 관계 행렬과 임계값·최종 오차 변경 |
| 관계 차이 집계 | 전체 차이 행렬의 모집단 표준편차 사용 | 두 컬럼의 관계가 반대인데 오차가 0이 되는 사례 해소 |
| 범주형 분포 | 카이제곱 p값 대신 `1-TVD` 사용 | 새로운 범주·단일 범주 처리 가능, 범주 비율 기반 점수로 변경 |

앞의 세 항목은 동봉 안내서의 인쇄면 73·78쪽을 대조했다. `1-TVD`는 [SDMetrics TVComplement](https://docs.sdv.dev/sdmetrics/data-metrics/quality/tvcomplement)의 정의를 적용한 개선이며 안내서의 필수 요구로 주장하지 않는다. 이 도구의 세 지표만으로 안내서 전체 준수나 합성데이터의 종합 안전성이 입증되는 것은 아니다.

임계값은 평가식 버전 `2.0`, 원본 내용 해시·행 수·컬럼·유형·위험도 비교 컬럼·반복 조건과 함께 저장한다. 평가 시 이 조건이 다르거나 이전 형식의 파일이면 재산정을 요구한다. 기존 임계값·결과 파일을 자동 변환하거나 삭제하지 않는다.

기존의 두 모델 비교, 품질 동점 시 GaussianCopula 선택, 생성 10,000행, CTGAN 2,000 epochs, 한국어 로케일, 분할 100회·실제 실행 90분위수는 유지했다. 일차원 컬럼 점수의 소수 넷째 자리 반올림과 Cramér's V의 2×2 연속성 보정도 유지했다. 고유값이 많은 범주는 같은 카이제곱 수식을 `sum(O²/E)-n`으로 계산해 조밀한 교차표 메모리를 줄였다.

## 코드·파일 정리

- `synthetic.py`의 세 명령과 설정·입출력·생성·평가 모듈로 통합했다.
- 대체 구현 검증 후 `01_Threshold_Cal.py`, `02_Making_Data.py`, `03_Evaluation_Synthetic_data.py`, `evaluation_func.py`를 삭제했다. 호환 실행 파일은 남기지 않았다.
- `.env`의 경로 자동 읽기는 JSON 설정으로 대체했다. 경로는 설정 파일의 디렉터리 기준이다.
- SDV 2.2의 `Metadata`와 표 이름별 DataFrame API를 사용하고 의존성 버전을 고정했다. 다른 SDV 버전용 호환 분기는 두지 않았다.
- 로컬 `config.json`, `data/`, `outputs/`, Python 캐시만 폴더 내 `.gitignore`에 추가했다. 추적 해제·커밋·푸시는 하지 않았다.
- 완료된 두 폴더와 안내서 PDF는 작업 전후 44개 파일의 SHA-256을 비교해 변경 없음을 확인했다. 해당 두 폴더의 테스트는 재실행하지 않았다.
- 함수·메서드 문서 문자열 누락 없음, Python 10개 파일 구문 확인, `git diff --check` 통과. 대상 폴더에 테스트용 Excel·CSV·모델·캐시 산출물 없음.
- 사용자 승인에 따라 폴더명을 `synthetic_data`로 변경했다. 이름 변경 직후 파일 16개의 해시가 변경 전과 같음을 확인했으며, 이후 이 검증 기록과 루트 인계 문서의 상태·현재 경로를 갱신했다. 안내서 PDF와 `reference/`의 과거 커밋 링크는 보존했다.

## 입력·결측·출력 계약

- Excel 첫 시트의 헤더를 읽어 pandas의 자동 이름 변경 이전에 중복·빈 컬럼명을 거부한다. 원본·합성의 컬럼 집합이 같아야 하며 순서만 다른 경우 원본 순서로 맞춘다.
- 평가 유형은 원본에서 한 번 정한다. `column_types`는 평가용, `metadata_overrides`·`primary_key`는 생성용 설정이다. 숫자 코드는 필요하면 양쪽 설정에 범주형임을 명시한다.
- 이름·주소 등의 생성 메타데이터는 실제 입력에 맞게 설정한다. 예를 들어 `{"sdtype":"name","pii":true}`, `{"sdtype":"address","pii":true}`를 해당 컬럼의 `metadata_overrides` 값으로 지정할 수 있다. 기본키 `id`의 정규식 고유값 공간은 생성량보다 작지 않아야 한다.
- 분할 시드에는 `threshold.seed + 반복 인덱스`를 사용한다. 홀수 행은 뒤쪽 분할에 한 행을 더 둔다. 위험도·이차원 오차는 상위 분위수, 일차원 점수는 보완 하위 분위수로 산정한다. 유용성 지표에 적용하는 이 분위수 방식은 도구의 운영 기준이다.
- 일차원 지표는 컬럼별 결측을 제외하되 양쪽 유효값이 있어야 한다. 한 컬럼이라도 미계산이면 전체 평균을 평가 불가로 처리한다. 결측률을 별도로 보고하므로 분포 점수를 결측률 일치로 해석하면 안 된다.
- 관계는 쌍별 완전 관측값을 사용한다. 공동 관측 2개 미만·수치형 상수의 Pearson 관계는 평가 불가다. 범주형 상수의 Cramér's V와 총변동이 0인 ANOVA는 기존처럼 0이다. 필수 관계 하나라도 미계산이면 전체 이차원 오차도 평가 불가다.
- 임계값 산정 중 미계산 분할이 생기면 일부 반복을 골라 쓰지 않고 전체 작업을 중단한다. 최종 평가에서 미계산 값이 생기면 진단 보고서는 저장하되 종합 통과를 내지 않는다.
- 결과는 임시 Excel을 완성한 후 게시한다. 기본값은 기존 출력 보호이며 `--overwrite`에서만 교체한다. 실패하면 기존 결과를 보존하고 작업용 임시 파일을 정리한다. 원본·합성·임계값·평가 경로 충돌도 거부한다.
- 원본과 일치한 레코드는 출력·저장하지 않는다. 생성 데이터는 합성 Excel의 첫 시트에만 저장한다. 셀의 등호 시작 문자열은 수식이 아닌 문자로 저장한다.
- 생성 라이브러리 예외에는 원본 값이 포함될 수 있어 오류 유형과 단계만 알린다. 라이브러리 경고는 원문 대신 발생 건수를 기록한다. 평가 명령은 통과 0, 미달 1, 평가 불가·실행 오류 2를 반환한다.

## 실제 검증

2026-11-17 Windows, Python 3.13.2에서 실행했다. 분석 전용 임시 가상환경에 설치했으며 전역 Python과 완료된 두 폴더의 환경은 변경하지 않았다.

- 환경: `%TEMP%\etc-synthetic-analysis-20261117\Scripts\python.exe`
- 주요 버전: pandas 2.3.3, NumPy 2.5.5, SciPy 1.18.1, openpyxl 3.1.5, SDV 2.2.0, SDMetrics 0.33.0, CTGAN 0.13.0, torch 2.15.0.
- 의존성 확인: `uv pip check`에서 설치된 52개 패키지의 호환성 확인.
- 구현 완료 시 전체 실행: **38개 통과**, 건너뜀 없음. 테스트 러너 기록 시간 52.878초.
- 이름 변경 후 `synthetic_data`에서 전체 재실행: **38개 통과**, 건너뜀 없음. 실제 두 모델 통합 테스트를 포함했으며 테스트 러너 기록 시간은 90.765초다. 코드·PDF는 이름 변경 전과 동일하고 문서 경로·상태만 갱신했다.
- 기본 실행은 37개 검증과 실제 모델 통합 테스트 1개 건너뛰기로 구성된다. 실제 모델 테스트는 환경 변수로 명시적으로 포함한다.

모델 통합 테스트는 `socket.socket.connect`를 실패하도록 바꾼 프로세스에서 수행했다. 실제 업무 원본이나 API 키는 사용하지 않았고, 테스트 파일은 `TemporaryDirectory`에만 생성·정리했다. 소스 검토에서 생성의 중간 CSV 출력을 비활성화했고, 테스트 작업 디렉터리에도 지정된 원본·설정·출력 폴더 외의 파일이 생기지 않음을 확인했다.

초기 저장 실패 테스트에서 Windows 파일 핸들 누수가 발견되었다. ExcelWriter의 오류 경로에도 외부 파일 핸들이 닫히도록 고친 뒤 최종 전체 테스트에서 기존 결과 보존·임시 파일 정리를 확인했다. 최종 실행에는 해당 실패나 경고가 재발하지 않았다.

재실행 명령은 이 폴더에서 사용한다.

이름 변경 확인 중 저장소 루트에서 실행한 첫 시도는 모듈 검색 경로가 달라 테스트 3개 모듈의 import 단계에서 실패했다. 코드 변경 없이 아래와 같이 대상 폴더에서 실행해 전체 통과를 확인했다.

```powershell
$analysisPython = Join-Path $env:TEMP 'etc-synthetic-analysis-20261117\Scripts\python.exe'
& $analysisPython -B -m unittest discover -s tests
$env:SYNTHETIC_MODEL_TESTS = '1'
& $analysisPython -B -m unittest discover -s tests
Remove-Item Env:SYNTHETIC_MODEL_TESTS
```

## 미검증 범위

- 실제 기관 데이터, 기관별 최종 모델·설정·점수와 과거 업무 결과의 재현.
- 기본 10,000행·2,000 epochs의 장시간 학습, GPU 실행, 대용량 전체 파이프라인의 시간·메모리 한계.
- 다른 Python·OS·패키지 버전 및 하드웨어 사이의 학습 결과 일치.
